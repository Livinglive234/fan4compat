# Fan4Compat 0.1.0-beta.40

Adds the **shared explored map** (Xaero's World Map 1.46.0). Terrain that any player has explored now appears on everyone's World Map,
including areas you have never visited. It needs Fan4Compat on the **server and on every client**, and it is on by default (switch
"Shared explored map" in the settings).

The server looks at the chunks around players a few times a second, stores a surface summary of each (top block, biome, terrain height
and top height per column) per dimension, and streams new or changed ones to every Fan4Compat client in that dimension; a client reports
what it already has at join, so only new terrain is sent. The client writes the summaries into Xaero's own map data the way Xaero's writer
writes a chunk it has just read, only where Xaero has no tile, and leaves them marked so Xaero replaces them the moment you load that
chunk yourself. Surface only: no caves. The Overworld, Nether, End and the Aether are shared by default (`sharedMapDimensions` in
`config/fan4compat-xaero.properties` on the server, with `sharedMapCaptureChunksPerTick`); TARDIS interiors and ship chunks are not.
Everyone sees terrain other players explored, and server admins can read the stored data (`<world>/fan4compat/shared-map/`).

The server operator chooses where the terrain comes from with `sharedMapMode` in `config/fan4compat-xaero.properties`: `SERVER` (the
server's own capture, as above), `CLIENT` (clients upload what their Xaero has mapped; the server captures nothing), `BOTH` (the default:
server capture, plus uploads that only fill places the server has not captured) or `NORMAL` (Xaero's default behavior, nothing shared).
Uploads come from the surface tiles Xaero has loaded around the player, a few per frame, in small batches; the server takes them only for a
shared dimension the player is in, inside the world border, within a rate limit, and stamps them itself. They are not verified against the
world, so `CLIENT` mode trusts everyone with the mod.

Also fixes the minimap going blank inside a TARDIS parked in the Nether (found with beta 39): in a ceiling dimension the minimap only
draws World Map chunks while the World Map's dimension matches the real one, which the exterior's dimension never does; a new hook
(`TardisMinimapLayersMixin`) makes that check see the virtual location. `xaeroMapNativeCheck` now binds ten TARDIS hooks.

The minimap's coordinate display now shows the TARDIS exterior's coordinates instead of the interior's, and while the TARDIS flies it
follows the flight from departure to destination (using DWM's synced flight progress), then settles on the landed exterior. The map and
waypoints are unchanged in flight. The cave start inside a Nether-parked TARDIS now matches what Xaero itself computes in open air
(exterior Y + 4 rather than + 1), so a layer you explored in person is used with its stored cave start.

A TARDIS parked on top of the Nether roof now gets the plain top view of the minimap instead of a cave layer for its height, so the
roof terrain you explored shows completely instead of only the part mapped at one height; under the roof it still uses the layer at the
TARDIS's height.

Known issue: with the TARDIS parked in the Nether the minimap is still incomplete or on the wrong layer (the Overworld works). The
coordinates are right in both. See PROGRESS.md for what was checked.

Inside a landed TARDIS the minimap's compass and player arrow (north-locked or rotating) and the World Map's player arrow now follow the exterior's orientation (DWM turns a player
by the difference between the door's facing and the exterior's when they walk out). Xaero's entity radar shows nothing while you are in
a TARDIS, so interior entities no longer appear on the exterior's map.

Reflection fix, found from the compass: `CompatCalls.call` listed a class's methods to pick one, and that fails outright when another mod has
added methods naming classes that are not installed (Porting Lib's `IPlantable` on blocks and block states, in this pack). The
compass could not read the interior door's facing for that reason, and the same failure would have hit the shared map's reads of blocks and
block states. It now falls back to reading only the wanted method from the class's own bytecode and linking just that.

Troubleshooting: a new switch, "Xaero TARDIS diagnostics" (`xaeroTardisDiagnostics`, off by default, takes effect immediately), logs `[Fan4Compat TardisDiag]`
lines when they change: where the exterior is and how the compass is turned, and the cave start and layer the minimap is given. Failures (the
compass cannot read the door facing, and so on) are always logged once, with or without the switch.

Logging: every message Fan4Compat writes (diagnostics, warnings, the updater's notices) now goes through Minecraft's own logger, which is
what ends up in `latest.log`. It used `System.Logger`, which goes to Java's default logging and never reached the file, so these messages
(including the updater's and every `[Fan4Compat ...Diag]` line) were invisible in `latest.log`. New code uses `shared/GameLog`.

If anything about Xaero's internals does not match, the shared map switches itself off for that connection with one warning in the log
and the map carries on normally. Also: the reflection helper now matches `byte`, `short` and `char` parameters.

Validation: clean build and regressions pass, with tests for the summary format and its bounded codec (including an inflation bomb),
the server region store, capture planning and the relay, the chunk summarizer, and the client applier and queue against fixtures that
mirror Xaero's classes; the upload modes, tile reader round trip, server intake rules and the client sweep are tested the same way. `sharedMapNativeCheck` binds the hook on `MapWriter.onRender` and checks every World Map, Fabric networking and
lifecycle, and Minecraft member against the real jars. It has not run in game or on a dedicated server; the first real run is the real test
of the applier. This is a test artifact; auto-updaters ignore it until published.
