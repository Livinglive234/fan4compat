# Fan4Compat 0.1.0-beta.21

Targets solid terrain disappearing with shaders off, sometimes after drawing the
XM3. The beta 20 diagnostics captured stencil comparison/write-mask disagreement
between OpenGL and Minecraft's state cache. Point Blank scope callbacks and
Immersive Portals' normal stencil renderer both use raw GL stencil setters; these
now go through Minecraft's cache so subsequent setters cannot be skipped because
of those bypasses.

During nested portal rendering, Point Blank's scope callbacks and preparatory
clear leave the portal's stencil mask, comparison, operations and test enabled
state alone. Non-stencil clear bits remain intact. Ordinary scope rendering keeps
its existing stencil operations. Scope-specific stencil masking is suppressed in
portal views so it cannot overwrite the portal's mask; check gun/scope visuals in
those views as part of testing. No stencil-bit reservation or new renderer is added.

The scope hooks require supported Point Blank Fabric 2.2.0. The portal bridge and
ownership guard additionally require supported IP (metadata 6.0.6 in the supplied
6.0.7 jar). Iris, VS and DH are optional. These changes are client-only.

Diagnostics remain enabled, sampled and bounded. Restart, disable shaders, draw
the XM3, switch away and check solid terrain and portals. Repeat with shaders on.
Send `latest.log` if rendering still fails; diagnostic lines start with
`[Fan4Compat RenderDiag]`. JVM argument `-Dfan4compat.renderDiagnostics=false`
disables observation hooks while keeping the stencil fix.

Validation: clean build, regressions, bytecode and packaging pass. Tests reproduce
the cache bypass, execute generated redirect handlers with a recording backend and
check portal mask preservation. Native checks pin all invocation bindings against
real Point Blank, IP and Minecraft jars, including the interface/static handlers.
GPU/gameplay confirmation remains pending. This build is an Actions artifact and
draft release; auto-updaters ignore it until published following testing.
