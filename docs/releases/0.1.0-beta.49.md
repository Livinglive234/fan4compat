# Fan4Compat 0.1.0-beta.49

**Chest Tracker's button is now really removed from screens that cannot hold items (fix for beta 48).** Beta 48 only added those screens to Chest Tracker's blacklist, but the blacklist does not control the main inventory
button: Chest Tracker adds that button to every container screen, and the blacklist only stops it remembering a screen's contents (and drops the remember and rename sub-buttons). The icon therefore stayed on every screen. The
**Chest Tracker skips non-storage screens** switch (`chestTrackerScreens`, on by default, restart to change) now also removes the button from the 30 listed screens right after Chest Tracker adds it, on every screen init (including
window resizes), and clears Chest Tracker's own reference to it. The blacklist stays, so those screens are still not remembered as containers. Screens that hold items keep the button.

Validation: clean build, all tests (the test now fires the screen-init handler against stand-ins: a listed screen loses only the button, a screen that holds items keeps it, repeating is harmless) and a real-jar check of every Fabric and
Chest Tracker member the handler uses plus the 30 screen classes. Not run in game.
