# Fan4Compat 0.1.0-beta.35

Adds a settings screen to Mod Menu. It needs Mod Menu and Yet Another Config Lib 3
(neither is a dependency; without them Fan4Compat behaves as before and has no screen).

An **Updater settings** button opens a second screen with the automatic update switches
(check for updates, download automatically, include beta releases), saved to
`config/fan4compat-updater.properties` and applied at the next launch.

Fourteen options, saved in `config/fan4compat.properties`:

- Rendering: Apple GPU portal fixes, Point Blank scope stencil fixes, Freecam with
  Distant Horizons, Elytra Contrails wing trails, TARDIS model cache.
- Ships and portals: block portals on ships, ship-aware sound occlusion.
- Pack integrations: hide Eureka portal warnings, hide Jade while at a helm, Trinkets items
  in graves.
- Troubleshooting: Eureka debug logging, Point Blank render diagnostics, Distant Horizons
  render diagnostics, portal depth-copy logging.

The portal depth-copy logging that was on by default since beta 24 is now off by default like the
other diagnostics; turn it on when investigating nested-portal rendering.

Everything defaults to its previous behavior (except portal depth-copy logging, now off), so nothing else changes unless you change it. Most
options apply after a restart; Trinkets in graves applies immediately. Options for mods you do
not have installed are greyed out. Fixes that protect saves or prevent crashes are deliberately
not switchable. `-Dfan4compat.feature.<key>=true|false` overrides the file for one launch, and the
older diagnostic JVM arguments still work.

Validation: clean build, regressions and packaging pass, including new tests for the switch
registry and the screen's reflective calls (YACL fixtures). `configNativeCheck` verifies every
YACL and Mod Menu member used against the real YACL 3.8.2 and Mod Menu 11.0.4 jars. The screen
has not been opened in game. This is a test artifact; auto-updaters ignore it until published.
