# Fan4Compat 0.1.0-beta.53

**The Aether portal works with Immersive Portals without a patched Aether jar.** The Aether 1.5.11 ships a data pack that turns its portal into an Immersive Portals portal, and a method that registers it
(`setupImmersivePortalsPack`), but `packSetup` never calls that method, so lighting the portal only made water pour down
([The-Aether-Team/The-Aether#2851](https://github.com/The-Aether-Team/The-Aether/issues/2851)). A new mixin calls it at the end of `packSetup`. It registers the pack once per pack event, so an Aether jar that already calls
it (a fixed build or one patched by hand) is not registered twice and the patched jar is no longer needed. New switch **Aether portal works with Immersive Portals** (`aetherPortalPack`, on by default, restart to change).
Aether 1.5.11 with a supported Immersive Portals only; the mixin stays off for any other Aether version.

**Internal cleanup of the beta 52 Sodium 0.8 code.** The three Sodium 0.8 hooks share one failure latch (`FailureLatch`), the ship hook reuses the shared field reader, and some dead code was removed. No behaviour change.
The remaining cleanup ideas are listed in `docs/release-readiness.md`.

Validation: clean build, all tests (including a new one for the once-per-event registration) and a real-jar check that `Aether.packSetup` and `Aether.setupImmersivePortalsPack` exist with the expected signatures. Run in game on a Mac with the stock Aether 1.5.11 jar (no hand-made fix) and Immersive Portals: the Aether portal forms.
