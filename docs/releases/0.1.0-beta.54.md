# Fan4Compat 0.1.0-beta.54

**Better End and BCLib recipes load again on BCLib 30.5.4 and 30.5.6.** Fan4Compat's BCLib fix was pinned to BCLib 30.4.0, so on the 30.5.x builds it was skipped ("Skipping compatibility hooks for bclib") and every custom Better End recipe
failed to parse: with Better End 30.5.6 the log showed 75 errors of the form `Parsing error loading recipe betterend:…: No key item in MapLike[{…"id":…}]`, one for every infusion (46), `bclib:smithing` (21) and alloying (8) recipe, so those
recipes were missing in game. BCLib's recipe codec still reads the result as `item` while the data reaches it as `id`; the fix lets the codec fall back to `id` and renames `id` to `item` in recipe results. BCLib 30.4.0, 30.5.4
and 30.5.6 are now accepted; other BCLib builds are still skipped. The recipe repair also covers BCLib 30.5's `bclib:smithing` recipes (the old `bclib:anvil` type's successor).

Better End Remastered 30.5.6 requires BCLib Remastered and WorldWeaver Remastered 30.5.6 or later, so use all three at 30.5.6.

Validation: clean build, all tests (including a new check of the accepted and rejected BCLib versions). Run in game on a Windows PC with BCLib, WorldWeaver and Better End 30.5.6 on Sodium 0.8.13: the recipe errors are gone and the recipes load.
Not run: the full real-jar check of the BCLib hooks (it needs every pack jar supplied; only BCLib was available); `ItemUtil.CODEC_ITEM_STACK_WITH_NBT` and its static initializer were confirmed present in the 30.5.6 jar.
