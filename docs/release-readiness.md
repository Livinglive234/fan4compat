## Move from alpha to beta

Freeze the existing supported feature set and test the same release candidate
on both client and dedicated server using the pinned mod versions. Optional
integrations should also be checked with their target mods absent.

- Clean build, generated bytecode verification and packaging checks pass. Alpha
  35 already passes these checks; repeat for the actual release candidate.
- Repeat TARDIS entry/exit on stationary and moving ships, landing/recall, and
  mining/placement through the doorway. Confirm player dimension, inventory and
  movement agree after repeated crossings, without loops, launches or freezes.
- Save a ship waypoint, travel away while the same ship moves, return using it,
  then repeat after a server restart. Verify unavailable status after reassembly,
  removal and normal access rules. The earlier reassembly report does not
  establish failure for an unchanged ship.
- Save/reload a ship-mounted TARDIS and a normal TARDIS, reopen doors, and check
  coordinates, independent destination/previous positions and scan preferences.
- Verify contrails, biome labels, helm/Jade behavior and portal-creation guards
  in the actual pack. Test the supported shader setup enabled and disabled.
- Compare normal play and repeated crossings for recurring exceptions, stalled
  chunk loading or increasing memory/tick cost. No reproducible crash, lost
  inventory, corrupted saved data or broken core interaction remains unresolved.

The singleplayer categories above are confirmed by the pack owner; do not treat
them as still untested. Repeat the corresponding workflows on a dedicated
server. If runtime code changes before release, repeat affected checks on the
new candidate. Log warning count alone is not a release criterion.

After this pass, publish 0.1.0-beta.1 with exact supported versions, installation
instructions, test results and known limitations. No new feature is required
merely to change the label.

## Move from beta to stable

Run the beta during normal singleplayer and dedicated-server play across several
sessions, including restarts and moving ships. Resolve reproducible regressions,
repeat affected checks, then produce a clean tagged 0.1.0 release. Verify the
published artifact, source link and release notes match that tag. Any remaining
limitation must be documented and must not break the supported core workflow.

Create/Flywheel shader integration and WWOO grid seams do not automatically block
release of the existing compatibility bridges. Unsupported integrations must not
be advertised as supported. The pack owner accepts the older Amendments,
IronChest and BetterEnd cosmetic warning candidates as low priority.

## Wishlist / forward thinking

- **Load and render the exterior ship through the TARDIS entrance before
  stepping out**, including opening from inside after the doors were closed or
  after a new entrance portal was created. Support stationary and moving ships
  without permanent global chunk tickets, movement freezes or teleport loops.
  This remains a known limitation and future work, not a beta/stable blocker.
- Create/Flywheel GPU rendering with Iris shaders and Immersive Portals, if a
  supported shader bridge can be implemented and tested.
- Revisit WWOO / Distant Horizons grid seams only with a demonstrated fix whose
  generation cost is acceptable; the alpha 34 border experiment remains removed.
